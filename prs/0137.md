## Description

# Fix activity-supervision escapes on open and on close

Fixes [#135](https://github.com/aarmea/lunchbox/issues/135). Fixes [#136](https://github.com/aarmea/lunchbox/issues/136).

Both issues turn out to be two directions of one defect: **the engine's session
lifetime is decoupled from the activity's lifetime**. `CoreEngine` holds a
single `Option<ActiveSession>` with no state between "running" and "gone", and
both transitions out of it `take()` the session unconditionally — without ever
confirming the activity actually started, or actually stopped. Nothing
reconciles that against reality afterwards.

Reconstructed from the `copernicus` journal and `shepherdd.db` of 2026-08-20.
Full write-up in `docs/ai/history/2026-08-20 001 activity-supervision-escapes.md`.

## [#136](https://github.com/aarmea/lunchbox/issues/136) — escape on close

The reported symptom was RetroArch surviving a close. What the journal shows is
worse: the *next* activity was the one that lost supervision.

```
19:48:37.130  shepherd_hud::app: Requesting end session          # press 1, HUD close
19:48:37.142  Session stopped 4b005e86 (tetris) reason=UserStop  # engine session gone at t=0
19:48:37.161  shepherdd::hidpi: Restored sway output scales      # 40ms BEFORE SIGTERM is sent
19:48:37.201  ...SIGTERM to retroarch
19:48:40.677  Launch requested entry_id=bitwig-studio            # press 2, landed on the grid
19:48:42.251  Sent SIGKILL via command name (timeout)            # t=5.1s
19:48:42.278  Session started 4376577d bitwig-studio
19:48:42.338  Process exited pid=93420 signaled=true signal=9    # RetroArch's reap
19:48:42.345  Session ended   4376577d bitwig-studio duration_secs=0
```

Three separate defects compounding:

1. **`stop_current` announced the end before doing the work.** It settled usage,
   broadcast `SessionEnded`, and restored the compositor scale — all *before*
   calling `host.stop()`. The comment on the restore said so outright: "before
   tearing down the process so the launcher reappears at its normal size". The
   launcher was designed to come back while the activity was still running.

2. **The second press was never meant for the grid.** It was a gamepad press,
   and the launcher polls `gilrs` — raw evdev — on a 16ms timer, so it never
   goes through the compositor and is not gated by focus. `launch_selected()`
   only checked that a tile was selected and sensitive.

3. **Exit events were never matched to a session.** The monitor reports a
   fabricated session id and identifies the activity only by handle payload;
   nothing compared it. RetroArch's SIGKILL reap landed 24ms after Bitwig's
   session started and ended Bitwig instead. The audit record carries the
   proof: `exit_code: null`, which is `ExitStatus::signaled(9)`.

Bitwig was left running with no session, no `session_info`, and no UI to close
it. Its gamepad-bridge sidecar leaked too — pid 93535 was still logging 64
seconds after shepherdd exited, under a different user's session.

Building the fix surfaced **two more escapes** the journal never showed:

4. **The spawned process is not always the activity.** A launcher script that
   backgrounds the real program and exits is reaped in milliseconds, and the
   monitor called that an exit — ending the session under a live window.
5. **The only process-group kill lived on `ManagedProcess`**, which is dropped
   the instant the spawned process is reaped, leaving a surviving descendant
   unreachable.

## [#135](https://github.com/aarmea/lunchbox/issues/135) — escape on open

```
19:36:44.052  WARN Steam game did not launch within timeout  app_id=1332010
19:36:44.086  Session ended fae168f7 steam-stray duration_secs=60
                          ---- no session active ----
19:37:01      steam: chdir ".../steamapps/common/Stray"
19:37:01      steam: Adding process 91059 for gameID 1332010   # 17s after we gave up
19:37:30.210  Session started 360032ff cluefinders             # launched ON TOP of it
```

Timing out does not cancel a Steam launch, because nothing can — `rungameid` is
a request to the long-lived preloaded client. The watchdog's teardown was a
no-op by construction (it only reaches the deadline on iterations where
`find_steam_game_pids` was *empty*), and it then deleted the `steam_sessions`
entry, which is the only thing the monitor tracks.

**Accounting damage:** usage recorded `steam-stray = 256s` against 245s of real
play — 120s billed for a game that never started, and 110s of actual play never
metered. On a time-limited entry that is a straight budget loss.

## Also fixed

- **Every launch failed to parse its own response.** The server's
  `LaunchOutcome` is externally tagged; the IPC client's mirror was
  `#[serde(untagged)]`, which can never match. Masked for approvals, *not* for
  denials — `Denied { reasons }` never decoded, so a child who is out of time
  saw the grid come back with no explanation.
- **Firewalled activities had no working teardown.** The helper's `stop-scope`
  subcommand had no callers anywhere, and the scope name was not recorded on
  the session. `ManagedProcess::command_name` was `argv[0]`, which under
  firewall enforcement is `pkexec` — useless against the activity and able to
  signal unrelated privileged operations.

## What changed

Teardown is now two-phase and the session stays *current* throughout:
`begin_stop` marks it stopping and hands back the handle; `finish_stop` settles
and clears once the host confirms. Since `request_launch` already refuses while
a session exists, **holding the session is what refuses the stray press** — at
the one layer that covers every input path, gamepad included.

| Commit | |
| --- | --- |
| `fix(ipc)` | Decode `LaunchOutcome` as the server sends it |
| `test(host-api)` | `MockHost` can model activities that ignore signals |
| `fix(core)` | Match exit events to the session that owns them |
| `fix(core)` | Hold the session until teardown actually finishes |
| `feat(api)` | `SessionState::Stopping` so shells can show a closing state |
| `fix(launcher)` | Ignore launches unless the grid is the active view |
| `fix(host)` | Confirm a kill instead of assuming it |
| `fix(host)` | Treat the process group, not the spawned pid, as the activity |
| `feat(host)` | Keep working on activities that escaped teardown |
| `fix(core)` | Don't charge for a launch that never started |
| `fix(steam)` | Don't orphan a game that launches after we gave up |
| `fix(host)` | Tear down a firewalled activity's systemd scope |
| `docs(ai)` | The investigation write-up |

Wire change: `SessionState::Stopping`. Kotlin regenerated via
`cargo run -p shepherd-wire-codegen --bin rpc-codegen`; the web UI's
hand-written union and status-colour map updated to match.

### Running the firewall tests

`#[ignore]`d and self-skipping, like the existing `firewall_real*` family — they
print `[SKIP]` and pass without the prerequisites, so CI is unaffected.

```sh
sudo ./scripts/integration-tests/setup-firewall-dev.sh
cargo test -p shepherd-host-linux --test firewall_teardown -- \
    --include-ignored --test-threads=1 --nocapture
```

No re-login needed despite the installer's warning: polkit's `subject.isInGroup`
reads the user's NSS record, not the calling process's supplementary groups, so
the grant is live as soon as `usermod -aG` lands.

## Deliberately not in this PR

- **Unowned windows are reported, not closed.** `report_unowned_windows` flags
  any surface belonging to nothing we track, but only *kills* activities
  shepherd itself spawned. Closing an unrecognized window is a policy call with
  real blast radius — a system dialog, something an admin started on purpose —
  and getting it wrong on a kiosk a child depends on is worse than the
  visibility gap. Happy to make it active if you'd rather.
- **No admin UI for orphans.** The audit log now answers "was supervision
  lost, and for how long?" but not "show me and let me close it".
  `list_windows` / `act_on_window` still exist only as debug methods.
- **RetroArch's specific SIGTERM behaviour is unverified** — handled by its own
  PR. The headless fixture reproduces the *shape* (window down early, process
  lingering past the deadline); that RetroArch does exactly this is inferred
  from the 5s gap in the journal, not measured.
