## Description

Ambient-light-driven backlight control. Maps the IIO `als` sensor's lux
to a target through a logarithmic curve, clamped by the existing
per-entry/global brightness restrictions so bedtime-activity dimming
still caps it. A manual slider drag temporarily overrides and auto
resumes on the next significant ambient-light change (phone-style).

Enabled via a `[service.brightness.auto]` config default plus a runtime
on/off toggle reachable from the HUD (IPC), the HTTP management API, and
BLE, persisted in the store across restarts.

- shepherd-host-api: read-only `LightSensor` trait.
- shepherd-host-linux: `LinuxLightSensor` reading `in_illuminance_raw`.
- shepherd-management: pure `auto_brightness` curve + manual-override
  state machine (unit-tested); `set_auto_brightness`/`toggle_auto_brightness`
  RPCs; shared `auto_brightness_tick` driven by a shepherdd poll loop.
- shepherd-config: `[service.brightness.auto]` schema/policy/validation.
- shepherd-store: generic `settings` key/value table for the toggle.
- shepherd-api: `BrightnessInfo.auto_{available,enabled}`; `auto_enabled`
  on the `BrightnessChanged` event.
- HUD + webui: auto toggle, shown only when a sensor is present.

Auto applies through the same clamp as manual sets but bypasses the
`allow_change` gate, since it is a parent-enabled system behavior rather
than a child-initiated change.
