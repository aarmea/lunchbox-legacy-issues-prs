## Description

Fixes [#73](https://github.com/aarmea/lunchbox/issues/73)

On suspend/resume the compositor can't draw for seconds, leaving a stale
frame (old clock, battery, activity list) frozen on screen. Commit a
neutral "Loading..." cover before sleep so the frozen image isn't
misleading, then drop it on resume once fresh state arrives.

shepherdd now holds a logind "sleep"/"delay" inhibitor and, on the
PrepareForSleep pre-sleep edge, broadcasts a new SystemSuspending event,
waits a short grace period for clients to commit the cover frame, then
releases the inhibitor so the system sleeps. On resume it broadcasts
SystemResumed and pushes a fresh StateChanged so clients replace the
cover with up-to-date content.

The logind/NetworkManager watcher is generalized (renamed
spawn_recheck_watchers -> spawn_system_event_watchers) and now runs
unconditionally so the cover works regardless of internet gating; the
internet monitor just supplies an optional recheck channel.

The launcher UI gains a Suspending state mapped to the existing loading
view. The HUD is unaffected for now (its event match has a catch-all).
