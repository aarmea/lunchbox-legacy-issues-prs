## Description

`shepherd dev run` boots a nested Sway (WLR_BACKENDS=wayland) that needs a
graphical login session, so an agent or SSH user cannot bring up the stack or
screenshot the launcher. This adds `shepherd dev headless`, which boots the same
stack (sway.conf, config.example.toml, debug binaries) against the GPU-less
headless wlroots backend the e2e harness already uses — no login session, no
parent compositor, no GPU — and exposes a virtual output that can be
screenshotted and driven.

New `shepherd dev` subcommands (scripts/lib/headless.sh):
  headless [--config PATH] [--user NAME] [--size WxH] [--time "..."] [--gpu]
           [--no-build]   start a detached session; details in
                          dev-runtime/headless/session.env
  shot [out.png]          grim the virtual output to a PNG
  tree [raw]              swaymsg get_tree summary (app_id/focus/fullscreen)
  key / type / click      inject input (wtype + sway seat cursor)
  stop                    tear down and clean up

- --config boots an arbitrary shepherdd config by rewriting only the shepherdd
  -c line in a derived sway config; the static sway.conf path is untouched.
- --user runs the whole stack as another user via sudo (their groups, HOME, and
  default ~/.config/shepherd/config.toml) for a realistic session: dedicated
  0700 runtime dir, socket/PID discovery as the owner, reattach via sudo, and
  `grim -o OUT -` to stdout so the invoker owns the screenshot.
- --time sets SHEPHERD_MOCK_TIME for reproducible availability/bedtime/limits.

Also: new `agent` deps set (grim, wtype, jq), folded into `dev`; a `headless-dev`
project skill so /run and /verify use this instead of ./run-dev; and docs in
CONTRIBUTING.md, AGENTS.md, and docs/ai/history.
