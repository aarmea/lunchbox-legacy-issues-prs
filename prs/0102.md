## Description

Add an `apt update`/`apt upgrade` install path alongside the existing
release-asset download. The `deb` job's staged `.deb` is now also PUT to
Forgejo's Debian package registry (owner-level, distribution `stable`,
component `main`) via a new scripts/ci/publish-apt.sh.

Forgejo signs the repository metadata itself (key auto-provisioned at
.../debian/repository.key), so the `.deb` needs no signing — this resolves
the "GPG-signed .deb + APT repo" follow-up from the binary-releases design
without any key management. Uploads are idempotent (409 Conflict treated as
success) so release re-runs are safe.

Prereleases (tags containing `-`) are skipped so RC builds never reach
`apt upgrade` users; they still get the signed release asset for manual
testing. Publishing uses a dedicated PACKAGE_TOKEN secret (write:package
scope), leaving RELEASE_TOKEN unchanged.

INSTALL.md gains an "Installing from the apt repository" section.
