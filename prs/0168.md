## Description

Closes [#109](https://github.com/aarmea/lunchbox/issues/109)

7.0.0-31 registers extended advertisements again, verified three ways:
bluetoothctl on both radios, a shepherd-shaped payload, and shepherdd
itself going on air. So the affected range is -28 through -30, not
"everything after -27", and hosts still holding -27 should unhold.

Proving it end to end took a full companion pairing, which surfaced four
traps the skill sent the next agent straight into:

- Android 16 raises a consent prompt (pairingVariant=3) and puts nothing
  on the wire until it is confirmed, so waiting for the device's passkey
  before touching a prompt deadlocks. pair.sh now drives both rounds.
- Every device advertises as "shepherd" (8-byte cap), so the label match
  can tap a different machine on the desk and leave the daemon log empty.
  pair.sh takes DEVICE=<controller address>.
- The notification shade reflows between the dump and the tap; pair.sh
  verifies BluetoothPairingDialog actually opened before proceeding.
- smp_send_app_cback "Unexpected event:2" is logged on every pairing, not
  just a wedged phone. The skill pointed at a destructive Bluetooth
  settings reset for a normal line; it no longer does.

pair.sh also stops confirming a *mismatched* numeric comparison, which
defeated the point of checking the digits.
