## Description

A from-source `shepherd uninstall` deleted exactly the four files the .deb
ships as conffiles: /etc/sway/shepherd.conf, the polkit rule, the udev
rule, and the bluetoothd drop-in. dpkg records a checksum for each and
keeps that record through `apt remove` -- only purge clears it -- so once
the file is gone behind dpkg's back it reads the absence as a deliberate
admin removal and refuses to restore it. Not on upgrade, and not on
`apt install --reinstall` of the same version.

Switching a box from the source build to the apt package is a supported
path, and it left that box reporting itself installed while missing its
sway config and its bluetoothd drop-in. The session entry is not a
conffile, so it came back fine and still pointed at
`sway -c /etc/sway/shepherd.conf`: the Shepherd session appears in the
greeter, then drops straight back to it. The empty
bluetooth.service.d/ directory -- created by dpkg on unpack, its conffile
skipped -- is the visible tell. The polkit and udev rules went the same
way, quietly taking the firewall helper and the input-compat sidecars
with them. Reported on copernicus.

Guard `remove_path` itself rather than the four call sites, so every
uninstall step inherits it and a future one cannot forget: a path
dpkg-query resolves to an installed package is left alone with a warning,
and `uninstall all` says how many it skipped and points at `apt purge`.
DESTDIR staging skips the check, where ownership is meaningless.

Also single-sources the package name into install.sh, since the uninstall
path now needs it and package.sh already sources this file.

docs/INSTALL.md gains the recovery for boxes already in this state:
--force-confmiss, which is the override for conffiles dpkg believes were
removed on purpose.
