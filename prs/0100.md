## Description

The Build/Test/E2E/Clippy/Package jobs all keyed the cargo registry and
target/ under one shared cache key and launched together after `images`.
On a Cargo.lock change they all restore-missed, cold-downloaded the same
crates in parallel, and then raced to save the one key (write-once, so
three saves were wasted). The saved target/ was also whichever job won
the race, despite `--all-targets`/clippy/plain-build producing different
target/ contents.

Split the cache in two:
  * Registry (~/.cargo/registry + ~/.cargo/git) under one shared key,
    populated once by a new `warmup` job via `cargo fetch --locked`
    before any compile job runs. Compile jobs restore it read-only
    (actions/cache/restore), so there's no save race and no 4x cold
    download. --locked also fails fast on a stale committed Cargo.lock.
  * target/ under a per-job key, so the jobs no longer clobber each
    other's incremental artifacts.

fmt (no deps to compile) and android-media (own image + key) are left
as-is.
