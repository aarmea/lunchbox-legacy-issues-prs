## Description

Three fixes to the graphical config editor, found from one report. Also bumps
the version to 0.5.1.

---

### 1. Activities cannot be edited ([#192](https://github.com/aarmea/lunchbox/issues/192))

Typing into any field of an activity's "What it launches" section raised
**`Error: cannot write null; use unset`** and changed nothing. Reported against
*The Hobbit*'s book path, but the bug is not about books: it hits every activity
whose kind is written as a standard `[entries.kind]` table, including the
example config's `tuxmath`, whose command is just as uneditable.

**Cause.** The editor renders each activity from `view()`, the daemon's own
parser serialised to JSON — so every unset `Option` arrives spelled as `null`
(`open_at`, `command`). `KindEditor` hands the *whole* kind back on every
keystroke, and `EntryDetail` wrote it with a single `set` on `…kind`. `set` on a
key holding a standard table merges it key by key through
`merge_object_into_table`, which called `json_to_value`, which rejects null
outright. Nothing had to be null in the file for this to fire — only absent,
which is the normal state of an optional field. Kinds written inline
(`kind = { type = "process", … }`) took a different branch that already skipped
null members, which is why this looked ebook-specific: the ebook example happens
to be written as a standard table.

**Fix.** In `doc.rs`, a null member merged into a standard table now means
"absent", removing the key, exactly as `json_to_table` and `json_to_value`
already treated one — one rule for null instead of two. In the editor, a new
`kindPatches` helper diffs the kind the form hands back against the one it was
given and writes only the fields that changed, removing one that became null; a
change of type still replaces the kind whole. Several fields changing at once (a
RetroArch core swapping its name for a path) coalesce into one undo step.

The second half is what keeps the file readable. With only the document-model
fix, the first keystroke in the Book field writes every default the view filled
in:

```toml
 book = "~/Books/x.epub"
+args = []
+env = {}
+font_family = "Noto Serif"
+font_size = 16
+kiosk = true
+layout = "facing_first_centered"
+viewer = "okular"
```

Seven lines of "the default, spelled out" per activity touched, in a 50 KB file
that is mostly comments. With both, the same keystroke changes the one line it
should.

---

### 2. "Add an activity" offered five of the nine kinds

The dialog hard-coded its own menu and its own blank-kind construction, and both
had drifted from `KindEditor`. **Virtual machine, Emulated game, Book and
Custom could not be created at all** — they had to be written into the TOML by
hand before the editor would show them. The type menu also had no fallthrough,
so any kind it did not recognise was silently built as a media library.

Worse, its media activity was built as `library_id`, a field the schema has
never had; the required `library` was therefore missing, and a newly added media
activity failed validation.

Both lists now come from one module, `model/kinds.ts`, keyed by the generated
`RawEntryKind["type"]` — so a kind added to the schema is a compile error here
rather than an option nobody can pick. `KindEditor`'s nine-way `switchTo` and
the dialog now share its `blankKind`.

---

### 3. The path fields were slow to type in

Not the validator: on the 50 KB example config one keystroke costs **0.49 ms**
to apply and **0.78 ms** to re-project and validate.

The controls are controlled by the projection, and the projection is re-derived
120 ms *after* an edit. A plain `value={…}` field therefore cannot show a
character until the whole config has been re-parsed, and typing at speed fights
a value one or more keystrokes behind.

New `DraftTextField` keeps what is being typed locally and hands it onward on
every keystroke as before: the document still updates live, the TOML pane and
the validator still keep up on their own debounce, and the cursor never waits
for any of it. The draft is dropped on blur, when the projection is
authoritative again — the same shape `DurationField` already used for a
different reason. Applied to every free-text field in `KindEditor`, plus the
label, icon and disabled-reason fields.

### Tests

* `crates/shepherd-config-wasm/tests/preservation.rs` — two tests that fail on
  `main` with the reported error. One edits the Hobbit's path through the view,
  asserting the untouched optional fields are not written out; the other writes
  every activity in `config.example.toml` back as it reads, which is what shows
  this was never ebook-specific (it fails first on `tuxmath`).
* `shepherd-webui/src/config/doc/patches.test.ts` — `kindPatches`: only the
  changed field, removal rather than a null, nothing when nothing changed,
  whole-kind replacement on a type change.
* `shepherd-webui/src/config/kind-editing.test.tsx` — the editing path in a DOM:
  a keystroke writes one patch and echoes immediately; clearing the starting
  page removes the key; the two-field RetroArch change is one undo step; the Add
  dialog offers all nine kinds and builds `media` on `library`.

### Verification

`cargo test -p shepherd-config-wasm`, `cargo clippy --workspace --all-targets -D
warnings`, `cargo fmt --all`, and the web UI's `npm test` (116), `npm run
typecheck`, `check:boundary`, `check:coverage` all pass, as does the standalone
bundle build.

End to end, the rebuilt wasm artifact was driven from Node with the same JSON
the browser sends: the whole-kind write no longer throws and the config still
validates with zero errors, and the per-field path changes exactly one line.
Not clicked through in a real browser — the typing and dialog behaviour is
covered by the DOM tests rather than by hand.

### Noted, not fixed

Clearing an optional text field such as "Reader binary" writes `command = ""`
rather than removing the line. That predates these changes and is left alone.
