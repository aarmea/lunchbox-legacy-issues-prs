## Description

The HUD's "X" (End session) button now shows a confirmation prompt before
ending the running activity, since it is easy to hit by accident and many
activities lose unsaved state when force-closed. This is configurable
per-activity via a new `confirm_on_close` entry option, enabled by default.

Because a HUD graceful stop is indistinguishable from an API graceful stop
at the daemon (both are UserStop), the confirmation is enforced client-side
in the HUD only -- API stops, time/quota expiration, and process exit are
untouched and still close immediately, as the issue requires. The daemon
just carries each activity's confirm_on_close preference to the HUD via the
SessionStarted event and the SessionInfo snapshot.

- shepherd-config: RawEntry/Entry.confirm_on_close (serde default true)
- shepherd-core: SessionPlan.confirm_on_close, CoreEvent::SessionStarted,
  carried into SessionInfo
- shepherd-api: SessionInfo + EventPayload::SessionStarted confirm_on_close
  (serde default true for older payloads)
- shepherdd / shepherd-http: thread the flag through both SessionStarted
  broadcast sites
- shepherd-hud: confirmation popover parented to the "X" button. Autohide so
  it self-dismisses on focus loss/outside tap/Escape (keyboard interactivity
  scoped OnDemand only while shown so the bar never steals focus otherwise);
  the state tick also pops it down when the activity ends by other means.
  Opaque dark surface with explicit high-contrast colors (light Cancel/dark
  text, red End/white text) and a recolored arrow so it reads on any GTK
  theme.
- docs: config.example.toml, HUD README, webui SessionInfo type, design doc
