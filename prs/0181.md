## Description

Closes [#178](https://github.com/aarmea/lunchbox/issues/178).

On a display under ~720 logical pixels tall, a `type = "ebook"` entry with
`hud_orientation = "left"` clips the bottom of the bar — taking the activity
title and both page-turn buttons with it. The title ellipsizes, as the issue
says, and it is not enough.

## What was actually wrong

Issue [#171](https://github.com/aarmea/lunchbox/issues/171)'s scope note predicted this and named the fix: *"if a device ever
does run out of vertical room, this is the place to add the equivalent of
`READING_SLIDER_WIDTH`."* That equivalent was already there and silently doing
nothing.

`apply_slider_lengths` has asked for a shorter slider during a reading session
since [#160](https://github.com/aarmea/lunchbox/issues/160), on whichever axis the bar runs along. On the vertical bar that was
`set_height_request(66)` — and `.hud-vertical .volume-slider` carried
`min-height: 80px`.

**A CSS minimum is a floor GTK takes the _maximum_ of against the widget's size
request.** The floor won every time, so the whole of the [#160](https://github.com/aarmea/lunchbox/issues/160) overflow response
was inert down the side of the screen. Worth carrying forward as a general
trap: a swapped-axis rule may state the *axis*, never the *length*, when the
length is also a size request.

The budget that produced the 720 line — vertical bar, reading session,
backlight present:

| Region | px |
|---|---|
| bar padding (`.hud-vertical`, 12+12) | 24 |
| end-session button | 40 |
| battery icon + label | 40 |
| brightness box (button 40 + slider ≥80 + padding) | 132 |
| volume box (same) | 132 |
| analog clock face | 36 |
| `right_box` spacings (8 × 4) | 32 |
| container spacing | 16 |
| time display | 20 |
| **title, floored at 12 chars** | ~96 |
| **page box (2 × 44px touch targets)** | ~80 |
| `left_box` spacings (12 × 2) | 24 |
| **total minimum** | **≈670** |

Add a configured network check and it is ~710. The `flow_append` reversal puts
`left_box` at the bottom, so the overflow lands on exactly the title and the
page buttons and spares the end-session button — that ordering was right, there
was simply nothing that yielded.

## Three commits

**1. `fix(hud): let a reading session actually shorten the vertical bar's sliders`**

Approach A on its own: drop the CSS length floor to `0px` so the size request
gets through, and give the vertical bar its own shorter reading length. This is
a real bug regardless of what follows, and it is deliberately **droppable and
cherry-pickable** — it is the minimal fix for the reported issue. It recovers
~130px of the ~750 needed, which is a measurable gain but not the whole fix.

Also adds `SHEPHERD_HUD_DEBUG_FORCE_PAGE_BUTTONS` (debug builds only), because
the headless session has no reader to start and both [#171](https://github.com/aarmea/lunchbox/issues/171) and [#178](https://github.com/aarmea/lunchbox/issues/178) previously
had to add a throwaway override to look at this layout at all. It forces
*visibility* only — the button handlers still check the real session, so a
stray press cannot page an unrelated activity.

**2. `feat(hud): open the volume and brightness sliders out of their icons`**

The actual fix, and the one that supersedes commit 1. A pair of inline sliders
is ~200 logical pixels of a 1280px bar and **over a third of the minimum height
of the vertical one**. Rather than ration that, take them out of the bar: each
icon now opens a flyout holding a toggle, the slider and the percentage, the
way a tray volume control behaves on every desktop. The bar pays for a 32px
icon apiece; the slider gets more room than it ever had inline.

The clock glyph beside the countdown goes too — a countdown is self-describing,
and it was the one thing on the bar saying nothing the numbers did not.

**3. `fix(hud): point the page arrows at the pages, and centre the countdown`**

Two nits from reviewing the screenshots. The page arrows were rotating with the
bar (`⌃`/`⌄` in a column); they point at the *pages*, not the buttons, so they
are `‹`/`›` in both layouts now. And the countdown was pinned to the left edge
of the vertical bar — a vertical box hands every child the full bar width and
`TimeDisplay` packs its label at the start of it, so centring has to be asked
for, exactly as the rotated title already did.

## What this retires

All of it dead once the slider is a popover child rather than a bar child:

- every `.hud-vertical` slider rule — a popover keeps its own horizontal axis
  whichever edge the bar is on;
- both `set_inverted` calls, which existed because GTK puts a vertical range's
  minimum at the top;
- `apply_slider_lengths`, `READING_SLIDER_WIDTH`, and the vertical reading
  length commit 1 added — the flyout has one length and never gives any back;
- the `!vertical && !can_turn_pages` juggling of both percentage labels. They
  were dropped from the vertical bar ("100%" does not fit across 48px) and from
  a reading session (no room); the flyout has room in every case;
- the `auto_updating` re-entrancy guard;
- `volume::get_volume_status` / `brightness::get_brightness_status`, which each
  built a Tokio runtime and connected **synchronously on the GTK main thread**
  to seed a slider that is now hidden until it is asked for. The 500ms timer
  seeds it from cached state instead.

## Two things for the reviewer

**`set_active` does not emit `clicked`.** Both toggles hang their RPC on
`clicked` rather than `toggled`, so the update loop can push the real mute /
automatic state back into the button every tick without echoing an RPC — which
is what the `auto_updating` guard existed to suppress. A wrong answer here is
an RPC storm, so it was measured rather than assumed: instrumenting both
signals and flapping `set_active` from the timer for 15s produced **20
`toggled` and 0 `clicked`**.

**The flyouts are rebuilt on every `HudScaleChanged`**, like the confirm
prompts and for the identical [#118](./0118.md) reason: they live hidden across the change
and are *measured* (`align_popover_to_button`) just before being shown. The
rule from the [#171](https://github.com/aarmea/lunchbox/issues/171) notes still holds — rebuild-on-scale-change is about
measurement, not visibility — and measuring is what puts these on the wrong
side of it. Their live state is re-pushed by the timer within one tick, while
they are still hidden.

**Behaviour changes worth a second opinion:**

- The bar's volume icon no longer toggles mute; mute moved into the flyout.
- The bar's brightness icon is no longer the automatic-brightness toggle. It
  still *reports* the state — the update loop puts the same highlight on it via
  `.brightness-manual` — but the toggle itself is in the flyout.
- Opening a flyout takes `KeyboardMode::OnDemand` for as long as it is up, the
  same trade the confirm prompts already make, because the autohide grab needs
  it. It goes back to `None` on close.
