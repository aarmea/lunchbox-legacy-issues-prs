## Description

Fixes [#27](https://github.com/aarmea/lunchbox/issues/27).

Adds a graphical editor for `config.toml`, living inside `shepherd-webui` and
building both into the management UI's bundle and as a standalone static site.

`schema.rs` is 1012 lines across 25 types, `validation.rs` is 1377 lines of
semantic rules, and `config.example.toml` is 926 lines. Hand-authoring that from
docs is where the mistakes are.

Design doc, including everything below in more detail:
[`docs/ai/history/2026-08-19 002 config-editor-webapp-scope.md`](docs/ai/history/).

## Two commitments everything else follows from

**It runs the daemon's own validator.** `crates/shepherd-config-wasm` compiles
`shepherd-config` to wasm32 and calls `parse_config`. Not a TypeScript
reimplementation of `validation.rs` — a second validator would drift from the
first within a release.

**It never regenerates the file.** Edits are surgical `toml_edit` mutations, so
comment preservation is a property of the architecture rather than a feature
that can regress. `config.example.toml` is 36 KB of which only 10 KB survives a
serde round-trip; a config people hand-annotate is a config they will not let a
tool rewrite.

The suite that holds that line is `tests/preservation.rs`: applying one patch to
`config.example.toml` changes **exactly one line**, every comment survives, a
trailing `# one hour` stays on its value, an unchanged write costs no undo step,
and undo is byte-exact.

## What it does

Graphical where the data has a geometry, forms elsewhere.

- **Availability is a week you drag on.** Create windows by dragging, resize by
  the edges, Alt-drag to pull one day out of a multi-day window. A category's
  windows show behind an activity's, with the intersection — what the engine
  actually enforces — outlined.
- **Budgets are sliders** on a non-linear scale, with the inherited value
  (service default, or the category's) drawn on the track, and an explicit
  "unlimited" detent because `0` means unlimited in `policy.rs`.
- **Warnings are markers** on a bar as long as the session, so
  `WarningExceedsMaxRun` is unrepresentable rather than merely diagnosed.
- **Token gates** get a source picker that knows the four self-unlock rules, and
  a graph of where time flows.
- Firewall rules, URL lists, env maps and paths stay forms. They have no
  geometry and widgets would only add clicks.

Every gesture has a keyboard equivalent and the selected window always has plain
`HH:MM` fields beside it.

### Three engine behaviours it draws honestly

Worth knowing when reviewing the grid, because all three are easy to get
backwards:

1. **No windows means available all week.** An unconfigured activity renders
   fully lit, not empty.
2. **One window can span several days.** `days = "weekdays"` is a single object
   across five columns; dragging any of them moves all five.
3. **A window that wraps midnight does not cross into the next day.**
   `TimeWindow::contains` tests the day mask against the weekday of the
   *instant*, so `["fri"] 22:00-02:00` means two disjoint chunks on Friday. The
   grid draws exactly that, with a note saying why.

## Not reachable from the management UI

The editor ships in `shepherd-webui` but is deliberately **not routed** from the
management UI, and `src/App.tsx` says why where the route would go.

Its only `ConfigSource` reads and writes files on whatever computer is browsing,
so a "Config" tab in a device's own web UI would read as "edit this device's
configuration" while doing nothing of the sort. That waits on a
`DeviceConfigSource`, which waits on **privilege separation in `shepherd-http`**:
a config write runs arbitrary commands (`kind = { type = "process", command =
... }`), and one blanket `require_auth` currently covers all of `/api/v1`, so any
token that can read usage stats could call it.

Leaving it unrouted also keeps its chunks and its ~800 kB wasm out of `dist/`,
so **the daemon binary is unchanged** — `dist/` is still 1.7 MB, exactly what it
was before this branch.

## Review notes

Where the interesting decisions live:

| | |
|---|---|
| `crates/shepherd-config-wasm/src/doc.rs` | The patch engine. Three rules make it preserve everything: entries and groups are addressed by `id`, `set` compares before writing, and replacing a value carries the old decor across. |
| `crates/shepherd-config-wasm/src/windows.rs` | Availability expanded to per-day spans, mirroring the engine including the cross-midnight rule. |
| `shepherd-webui/src/config/components/SubjectDetail.tsx` | One detail view for activities and categories. `RawGroup`'s fields are a strict subset of `RawEntry`'s, which is what makes it well defined. |
| `shepherd-webui/src/config/navigation.ts` | Why a focus request is one-shot. Pages are conditionally rendered, and a mount runs every effect regardless of deps. |

Toolchain and CI:

- `wasm-pack` and the wasm32 target join the build/dev deps sets, so the CI
  image picks them up from `scripts/shepherd deps install build`.
- Two new CI jobs: `webui` (boundary, coverage, tests — no Rust needed) and
  `config-editor` (wasm + standalone bundle + typecheck).
- `shepherd build config-editor`, `shepherd build config-wasm`, and
  `shepherd dev webui [--standalone]`.

## Verification

106 tests: **54 Rust**, **52 TypeScript**, plus four static guards
(`tsc`, import boundary, schema coverage, codegen drift).

- The generated TypeScript mirrors of `RawConfig` are covered by the existing
  `shepherd-wire-codegen` drift test.
- `check:coverage` fails if a schema field is unreachable from the UI. It reads
  *names*, so it cannot see a sub-table wired to one parent and not another —
  its own header says so.
- The patch wire contract is pinned from both sides against one shared fixture,
  so a renamed serde tag fails a test instead of breaking the editor silently.
- `cargo tree` finds zero occurrences of `wasm-bindgen` or `schemars` in the
  default build or in `shepherdd`.

Driven end to end in a browser: loads `config.example.toml`, renders all 15
entries, draws Tux Math's two windows correctly, shows Celeste's inherited
limits and its token graph, and reports "Valid".

## Before this deploys

The Cloudflare pipeline is written but has **never run**. It needs, all outside
this repo:

1. A Pages project named `shepherd-config-editor`, **Direct Upload**, with its
   production branch set to `main` — the job deploys `--branch main`, and a
   mismatch publishes every release to a preview URL instead.
2. An API token scoped to *Cloudflare Pages: Edit*, as `CLOUDFLARE_API_TOKEN`.
3. `CLOUDFLARE_ACCOUNT_ID`.
4. The custom domain `config.shepherd.armeafamily.com` on the project. It is a
   third-level subdomain, so watch that the certificate goes Active — Universal
   SSL covers only one level. Nothing in the repo encodes the hostname if it
   needs to change.

`release.yml`'s existing `workflow_dispatch` `publish` toggle covers the deploy
step, so the first run can be a dry build and the second a real deploy without
cutting a tag.

Deploys on `vX.Y.Z` tags, not on pushes to main: the editor renders a
`config_version` that ships with the daemon, and one running ahead of the
release would offer fields the installed version cannot read. Prerelease tags
are skipped, as the apt registry already does.

## Not included

- **Phase 3**: unknown-key lint, structured error paths, diff-before-save,
  templates, the week scrubber.
- **Phase 4**: `DeviceConfigSource` and the `get_config`/`set_config` RPCs,
  gated on privilege separation above.
- **Phase 5**: Tauri.
- Free-form JSON (`vm`/`media` driver args, `kind.custom.payload`) stays in the
  raw TOML pane — there is no schema to render a form from.
- Untested and named in the design doc so the next pass starts from a list:
  `replace_text`, `blank()`, the wasm binding layer itself, and most component
  interaction.
