## Description


Closes [#160](https://github.com/aarmea/lunchbox/issues/160). Closes [#162](https://github.com/aarmea/lunchbox/issues/162).

One activity per book, opening on the page the child stopped at, in a reader
locked down to reading it — plus the general stop-path fix that turned out to be
a prerequisite, and the HUD buttons that make a book navigable on a tablet.

Scoping notes, measurements and the decisions they settled are in
`docs/ai/history/2026-09-03 001 ebook-content-type-scope.md`.

## Why the reader is Okular, not calibre

The issue guessed calibre, and calibre gets the reading experience right. What
it will not do is stay out of the rest of the machine: a tap on the page opens
a menu with a file dialog over the whole filesystem, calibre's own *Edit book*
application, developer tools and a Google search — and nothing in calibre turns
any of it off. Patching it is out, by the rule the browser kind already states.

Okular can be locked down, through KDE's Kiosk action restrictions, which are
enforced by the framework (`KActionCollection` disables, hides and
signal-blocks a restricted action, so the menu item, the toolbar button *and*
the keyboard shortcut die together), immutable to the application via `[$i]`,
and not liftable by any environment variable. It also covers both halves of the
issue — EPUB and PDF — in one app, and its EPUB rendering passed the
readability check that could have sent us back to calibre.

## What is in the branch

**The `ebook` kind.** `shepherd-host-linux/src/ebook.rs` generates the reader's
whole configuration per entry — the Kiosk restrictions, the page-at-a-time view,
the reading font, and a local XMLGUI document to hide the toolbar (which is not
a config setting at all, but an attribute of the GUI definition) — into a
per-entry `XDG_CONFIG_HOME` / `XDG_DATA_HOME` / `XDG_CACHE_HOME`, re-rendered
before every launch because Okular rewrites its own config on exit. Reading
positions live under the same root and shepherd never writes them.

```toml
[entries.kind]
type = "ebook"
book = "~/Books/the-hobbit.epub"
```

Everything else — `layout`, `font_size`, `font_family`, `open_at`, `kiosk`,
`viewer`, `command`, `args`, `env` — defaults to what the Phase 0 pass measured
as working. Note `font_size`: with the page fitted to the screen it is the
reading-size knob rather than a detail, and changing it repaginates the book,
which moves a remembered position — so it wants choosing before the first read.

**The polite close ([#162](https://github.com/aarmea/lunchbox/issues/162)).** Okular installs no `SIGTERM` handler and writes its
reading position only when its window closes cleanly, so under the signal-only
stop path every session started again at page one. A graceful stop for a kind
that opts in now asks the compositor to close the session's windows first
(`[con_id=N] kill` over the sway IPC the daemon already holds), waits up to
three seconds, then falls through to the unchanged `SIGTERM` → `SIGKILL`
ladder. Opt-in per kind because a close request is not always a quit: Steam
reads it as "hide to tray", and RetroArch's single-`SIGTERM` shutdown is already
verified to save ([#125](https://github.com/aarmea/lunchbox/issues/125)). An activity with no window costs nothing — the wait
only happens if a window was found.

**HUD page-turn buttons.** Paging is bound to a key, a D-pad or a wheel; a
touchscreen produces none of those, and Okular grabs only the pinch gesture — it
has no swipe-to-turn. A reading session now adds `‹` and `›` to the HUD bar,
which synthesize `Page Up` / `Page Down` through the same `/dev/uinput` backend
the input-compat bridges use. The HUD is the right home for them: it is on the
overlay layer above the activity, and it is shepherd's own surface rather than
something a reader's own restrictions could take away.

**Diagnostics.** A book that is not where the entry says it is; a reader or
format backend that is not installed (Ubuntu packages Okular's EPUB support
separately, which makes it the likely first-run failure); and `EbookNoPageTurn`
for a paged layout on a device where neither a gesture nor the HUD buttons can
work — a touch-only device with no writable `/dev/uinput`.

## Setup

```sh
sudo shepherd-admin apps install okular
```

Installs `okular`, `okular-extra-backends` (EPUB and DjVu ship separately from
Okular itself) and `fonts-noto-core` for the default reading font. No books are
installed; a book from a store belongs in that store's app, per the issue.

`docs/ebooks.md` is the operator's page: which reader for which format, what
each restriction closes, where positions live, the touch story, and what this is
*not* (a supervision tool, not a security boundary).

## Verified

On hardware, in the headless dev session, against the real Okular:

- A six-line entry produces the chrome-free facing-pages view.
- `stop_current` writes the position (108 ms from the close request to a clean
  exit) and relaunching returns to the same spread. Under the old path the same
  stop wrote nothing at all.
- Two entries on the same book keep independent positions, with their own font
  and layout.
- `Ctrl+O` and `Ctrl+P` do nothing under `kiosk = true`, and open dialogs in an
  unrestricted control run — so "nothing happened" is the restriction, not a
  lost keypress.
- PDF works through the same kind.
- HiDPI: Okular takes `wp_fractional_scale_v1` at 2.0 and 1.5, renders the page
  raster at device resolution, and follows a scale change live. No
  `xwayland_native_resolution` needed.
- The HUD buttons emit exactly `KEY_PAGEDOWN` / `KEY_PAGEUP`, read back from the
  device node.

`cargo fmt`, clippy, 1033 tests, `config.example.toml` validation, and the webui
type-check / coverage / boundary / vitest checks are all clean.

## Not verified, and worth knowing

The headless harness has **no input devices at all** — its seat reports no
pointer, keyboard or touch capability, and the libinput backend needs a real
seat. So two things here are reasoned from source rather than measured: what a
finger does inside the reader, and the last hop of the page buttons (the
compositor reading a uinput device and delivering the key to the activity). That
hop is the one the touch and gamepad bridges already depend on, but it is worth
a look the first time a panel is set up.

## Follow-ups, not in this branch

- A touch page-turn *gesture* — tap zones in a sidecar, in the shape of
  `touch_to_mouse`. The HUD buttons make the activity usable without it.
- Cover art as the tile icon; it wants a place to run `ebook-meta --get-cover`
  that is not config parsing.
- A second `viewer`. The enum has one value today; zathura and mupdf are
  surveyed in the scope note but nothing is wired.
- Extending the polite close to plain `process` entries: a one-line change, and
  a judgement about stop latency for apps that ignore the request.
