## Description

Follow-up to [#117](./0117.md). That fix set a base `font-size` on
`.confirm-close-popover > contents` expecting the Cancel / End activity
button labels to inherit it. They don't: the GTK theme sets an explicit
`font-size` on the `button` node, and an explicit rule beats an inherited
value in the cascade. So under the counter-scale the HUD applies while an
`xwayland_native_resolution` activity holds sway at scale 1.0, the button
boxes grew (their `min-height`/`padding` are stated in px) but the labels
kept the theme's logical-pixel size and rendered 1/factor too small.

This is the slider-knob failure mode from [#117](./0117.md) (theme size wins the
cascade), not the warning-banner one (no rule at all): inheritance from
`> contents` was never going to reach the buttons.

Fixed by stating `font-size: 14px` on the `.confirm-close-popover button`
rule itself, which outranks the theme's bare `button` and, being a px
literal, follows the counter-scale. 14px matches the base [#117](./0117.md) chose for
`.hud-bar` and `> contents`, so the un-hacked HUD is unchanged. New
regression test asserts the button rule declares a font-size.

Verified in the headless dev session against a two-entry fixture identical
but for `xwayland_native_resolution`: under the hack the button labels go
from ~30% smaller than the scale-1.5 reference back to matching it, while
the message label (already at an explicit 15px) was correct throughout.

Fixes [#114](https://github.com/aarmea/lunchbox/issues/114)
